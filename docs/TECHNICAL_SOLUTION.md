# 方太个性化膳食规划 Agent 技术方案

版本：2026-08-22

## 一、项目概述

本项目面向家庭膳食规划场景，基于用户健康档案和自然语言需求，从官方菜谱库中检索并组合个性化菜单。

系统采用“结构化约束识别、官方菜谱检索、本地规则校验、营养估算和多轮会话管理”的技术路线，确保推荐结果真实、可验证、可解释。

## 二、设计目标

1. 推荐菜品必须来自官方菜谱库；
2. 过敏和明确忌口必须零违反；
3. 支持多人、健康目标、餐次、菜品数量和口味等复合条件；
4. 支持多轮修改并尽量保留原有菜单；
5. 营养结果可计算、可解释并保留估算置信度；
6. 支持公网 API、网页演示和 Docker 部署；
7. 外部模型不可用时，系统仍可使用本地规则完成核心推荐。

## 三、系统架构

```text
用户或评测器
        |
        v
HTTP API / 网页演示
        |
        v
会话管理与历史重放
        |
        +--> 约束识别
        |       +--> 本地规则
        |       +--> 可选模型辅助
        |
        +--> 官方菜谱检索
        |
        +--> 过敏与健康校验
        |
        +--> 菜单组合与最小修改
        |
        +--> 营养计算与评审
        |
        v
结构化 JSON 与中文解释
```

## 四、数据来源与处理

系统运行时读取：

- 官方菜谱数据；
- 用户健康档案；
- 对话测试用例。

菜谱名称、食材、步骤和标签以本地数据为准。系统不允许外部模型直接生成新菜名。

健康档案用于提供年龄、性别、身高、体重、BMI、体检指标、特殊人群、过敏食材、健康需求和口味等约束。关键字段缺失时，系统拒绝加载不完整档案。

## 五、约束识别

系统从健康档案和对话消息中识别：

- 餐次；
- 用餐人数；
- 菜品数量；
- 过敏食材；
- 忌口和不喜欢的食材；
- 口味偏好；
- 减脂、增肌、控糖、降压、养胃等健康目标；
- 老人、儿童、孕期和哺乳期等特殊人群；
- 烹饪时间、难度和用餐场景。

系统区分硬约束和软约束。过敏、明确忌口、菜品数量和菜谱真实性属于硬约束；口味、排序、营养平衡和烹饪偏好属于软约束。发生冲突时，优先满足硬约束并输出说明。

## 六、菜谱检索与菜单规划

规划流程如下：

1. 读取官方菜谱库；
2. 根据硬约束过滤候选菜；
3. 根据餐次、人数、健康目标和口味进行排序；
4. 按菜品数量和菜品类别组合菜单；
5. 使用营养结果进行二次排序；
6. 生成可解释的推荐结果。

多轮修改时，系统比较上一版菜单和新候选菜单，优先保留仍然满足条件的菜品，只替换违反新增约束的菜品。

## 七、营养计算

本地营养模块计算：

- 总热量；
- 蛋白质；
- 脂肪；
- 碳水化合物；
- 膳食纤维；
- 糖；
- 钠；
- 人均营养；
- 缺失食材、估算假设和置信度。

营养数据用于菜单排序和结果解释，不作为医学诊断。营养评审可以由本地规则生成，也可以由外部模型辅助润色，但外部模型不能修改营养数值。

## 八、多轮会话与版本管理

系统支持：

- 使用 `session_id` 继续对话；
- 不带 `session_id` 时提交完整消息历史；
- 查看菜单版本历史；
- 指定版本回滚；
- 通过“撤销刚才修改”等自然语言回滚；
- 回滚后继续追加约束。

回滚会创建新的当前版本，历史版本保持不变。任何版本恢复都必须重新接受过敏和忌口校验。

## 九、外部模型调用边界

外部模型只用于：

- 复杂自然语言约束的结构化补充；
- 营养评审的文字组织。

外部模型不能：

- 生成菜品名称；
- 删除或修改硬约束；
- 将忌口改写为过敏；
- 覆盖本地营养数值；
- 绕过官方菜谱真实性校验。

系统设置独立超时和失败回退机制。外部模型超时、返回错误或未配置时，使用本地规则继续服务。

## 十、部署与安全

系统支持 Python 直接运行、Linux systemd 常驻运行和 Docker 容器运行。核心运行链路使用 Python 标准库和本地数据。

外部模型配置通过环境变量注入，敏感信息不进入源代码、镜像和版本库。官方数据、健康档案和运行配置按照交付环境单独管理。

## 十一、项目特色

- 官方菜谱真实性可验证；
- 过敏和忌口硬约束可追踪；
- 多人整桌推荐；
- 多轮菜单最小修改；
- 本地营养数值与结构化评审；
- 外部模型可选、失败可回退；
- API、网页和 Docker 多种交付方式。

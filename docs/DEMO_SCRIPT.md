# 方太个性化膳食规划 Agent 演示流程

建议时长：5-8 分钟
当前公网固定验收：8/8 通过，98.8/100，无超过 8 秒硬失败。

队友直接访问：

```text
http://47.116.110.131:8000/demo.html
```

本页面用于初始阶段演示录制，不需要录制 Docker 操作。页面内已经固定好演示输入和操作顺序，按左侧步骤依次点击即可。

## 一、系统介绍

系统根据用户健康档案和自然语言需求，从官方菜谱库中生成个性化菜单，并同步提供约束解析、营养估算、风险提示和菜单变化记录。

推荐菜品由本地菜谱库提供，外部模型仅用于复杂自然语言的结构化辅助，不参与菜品自由生成和硬约束裁决。

## 二、服务检查

打开演示网页：

```text
http://47.116.110.131:8000/demo.html
```

进入页面后，建议按照左侧“录制流程”从第 1 步运行到第 5 步。每一步点击“运行当前步骤”，等待右下角提示完成后再继续。

## 三、队友录制操作

1. 打开演示页，确认右上角显示“API 在线”。
2. 点击“连接服务”并运行，展示服务状态、2000 道官方菜谱和 50 份健康档案。
3. 点击“首轮推荐”并运行，展示 4 人午餐、4 道菜、官方菜谱和营养结果。
4. 点击“最小修改”并运行，展示“不吃鸡蛋，其他菜尽量别动”，确认菜单仍为 4 道且只替换必要菜品。
5. 点击“营养评审”并运行，展示“降压、减脂、清淡”约束、人均营养和风险提示。
6. 点击“版本回滚”并运行，展示菜单历史和当前版本回滚结果。
7. 录制结束时保留页面上的菜单、约束摘要、营养评审和“已回滚”结果 3 秒。

## 四、服务检查

也可以单独调用：

```http
GET /api/health
```

展示服务状态、菜谱数量和用户档案数量。

## 五、多人菜单推荐

输入：

```text
4个人吃午餐，先推荐4道菜。
```

展示：

- 识别用餐人数为 4；
- 识别餐次为午餐；
- 返回 4 道菜；
- 推荐菜品来自官方菜谱库；
- 页面展示营养信息和评分卡。

## 六、忌口修改

继续输入：

```text
我不吃鸡蛋，其他菜尽量别动。
```

展示：

- “不吃鸡蛋”归入忌口；
- 不被识别为过敏；
- 含鸡蛋的菜品被替换；
- 其他符合条件的菜品保留；
- `changes.mode` 为 `minimal_revision`；
- 用餐人数和菜品数量保持不变。

## 七、健康与营养评审

输入：

```text
我有高血压，也想减脂，推荐4道菜，尽量清淡一点。
```

展示：

- 同时识别降压和减脂目标；
- 明确要求清淡时，不再出现剁椒、辣椒粉、麻辣等明显辣味菜；
- 展示热量、蛋白质、脂肪、碳水和钠；
- 展示营养风险提示和饮食建议；
- 外部服务不可用时仍保留本地营养结果。

营养结果用于膳食规划和解释，不替代医疗诊断。

## 八、菜单历史和回滚

展示推荐结果中的 `session_id`，调用：

```http
GET /api/sessions/{session_id}/history
```

使用指定版本回滚：

```json
{
  "session_id": "上一轮返回的 session_id",
  "messages": [],
  "rollback_to": 1
}
```

展示：

- 历史版本按顺序保存；
- 回滚后创建新的当前版本；
- 原有历史不会删除；
- 回滚后仍执行过敏和忌口校验。

## 九、项目特点总结

- 菜谱来源真实可查；
- 过敏和忌口约束可验证；
- 支持多人整桌规划；
- 支持多轮最小修改；
- 营养结果可计算、可解释；
- 外部模型可选且具备失败回退；
- 会话续接不会重复等待外部营养评审；
- 提供稳定的公网 API 和网页演示。

## 十、首页手动输入与中转站辅助演示

如果需要展示队友手动输入需求，以及中转站对复杂自然语言的辅助解析，请使用首页：

```text
http://47.116.110.131:8000/
```

不要在主流程中展示 API 密钥、服务器环境变量或中转站配置。只展示页面返回的结构化结果。

### 1. 开始新的手动输入演示

1. 刷新首页；
2. “用户健康档案”选择“从对话自动识别用户特征”；
3. “官方对话用例”选择“自定义输入”；
4. 在“多轮对话”输入框输入：

```text
两位成年人加一个孩子吃午饭，整桌五道菜，不吃香菜。
```

5. 点击“生成推荐”；
6. 滚动到“约束解析”，展示 JSON 中的以下结果：

```json
{
  "meal": "午餐",
  "people_count": 3,
  "requested_dish_count": 5,
  "avoid_ingredients": ["香菜"],
  "inferred_profile": {
    "special_groups": ["儿童"],
    "llm_assist": {
      "enabled": true,
      "used": true,
      "applied_fields": ["people_count"]
    }
  }
}
```

### 2. 队友录制台词

“这里输入的是一个复杂的家庭人数表达。系统先使用本地规则识别餐次、菜品数量和忌口，再通过中转站辅助模型补全人数信息。”

“可以看到，外部模型只补充了 `people_count`，没有生成新的菜名，也没有修改过敏、忌口和营养结果。最终菜品仍然来自官方菜谱库。”

“如果中转站不可用，系统会自动回退到本地规则，仍然可以完成推荐。”

### 3. 建议展示顺序

首页手动输入演示建议放在主流程之后：

1. 先展示 4 人午餐、4 道菜；
2. 再追加“不吃鸡蛋，其他菜尽量别动”；
3. 展示高血压、减脂和营养评审；
4. 展示版本回滚；
5. 刷新首页，单独输入复杂家庭人数表达；
6. 展示 `llm_assist.used=true` 和 `applied_fields`；
7. 回到菜单结果，说明硬约束和菜谱真实性仍由本地逻辑控制。

中转站辅助属于可选增强，不是最终离线运行的必要依赖。录制时不需要展示 Docker、密钥或服务器配置。
